# Yozma 2.0: посты из разговоров с ИИ (дизайн)

Дата: 2026-11-12 · Статус: черновик, ждёт одобрения

Пометка «*(моё решение)*» означает решение, которое принял Claude, а не автор проекта. Его можно оспорить.

## 1. Зачем

Yozma — личный статичный блог: markdown в `posts/` → Next.js static export → GitHub Pages (yozma.uz). Автор давно не пишет: мысли теперь рождаются в разговорах с ChatGPT или Claude и там же остаются. Флоу «md-файл → коммит → готовый пост» автору нравится, его сохраняем.

Новая идея: интересный разговор с ИИ превращается в пост, почти без ручной работы. Автор говорит в чате «давай сделаем из этого пост». Модель задаёт несколько вопросов, пишет эссе от первого лица на узбекском (в новом латинском алфавите), проверяет орфографию через Tahrirchi и публикует пост в репозиторий. Публикация идёт либо сразу, либо через PR на аудит, на выбор автора.

Успех: автор снова публикует посты, и они звучат как он сам, а не как ИИ.

## 2. Цели, не-цели, анти-цели

**Цели**
- Пост из разговора создаётся прямо в ChatGPT или claude.ai, без терминала и с телефона тоже.
- Посты только на узбекском, в новом латинском алфавите, независимо от языка разговора.
- Способ публикации автор выбирает в момент публикации: «сразу» (коммит в `main`) или «на аудит» (PR).
- Правки по аудиту двумя путями: комментарии в PR (бот правит) и просьба в том же чате (инструмент `update_post`).
- На сайте появляются теги, отметка «tahrirlangan» с датой, пометка об ИИ-происхождении, черновики и диаграммы.

**Не-цели (сейчас)**: комментарии читателей, аналитика, CMS/админка, кириллическая или другие языковые версии, несколько авторов, публикация без явной команды автора.

**Анти-цели** (будет провалом, даже если технически работает):
- Текст звучит как ИИ: шаблонно, пафосно, «xulosa qilib aytganda», мораль в конце.
- Сайт теряет чистоту: градиенты, лишние тексты и декор на главной.
- Появляется база данных или сервер для самого сайта. Сайт остаётся «markdown в GitHub + статика».

## 3. Текущее состояние (что есть)

- `src/lib/getPosts.ts` читает `posts/*.md` (gray-matter), рендерит через `remark` + `remark-html`, форматирует даты через `moment`.
- Frontmatter: `title, date, author, keywords, description`.
- Баг: `getAllPosts` сортирует по уже отформатированной строке (`moment(...).format("LL")`), а не по дате.
- `.github/workflows/deploy.yml`: push в `main` → `pnpm build` → `peaceiris/actions-gh-pages` в ветку `gh-pages`, CNAME `yozma.uz`. Checkout без `fetch-depth: 0`.
- Интерфейс на английском, `<html lang="en">`, Tailwind 4 + typography, `bg-gray-100`, `prose lg:prose-lg`, Inter.
- Посты: `welcome-to-yozma.md` (узбекский, старая латиница) и `working-with-legacy-code-...md` (английский).

## 4. Части и порядок

1. Обновление сайта и общий модуль «узбекский текст».
2. MCP-сервер Yozma.
3. Бот правок в PR.
4. Контент: новый пост о Yozma и тексты сайта.

Каждая часть получает свой план реализации. Ниже идут требования к каждой.

## 5. Часть 1: сайт

### 5.1 Дизайн (решено с автором: вариант «A2»)
- **Главная выглядит как сейчас:** h1, вступительный текст, список «дата + заголовок». Никаких градиентов, цитат и декора.
- У постов из разговора с ИИ рядом с заголовком стоит маленькая фиолетовая `✦` (цвет около `#7c3aed`). Фиолетовый на сайте означает только ИИ и больше нигде не используется.
- Теги и «tahrirlangan» на главной **не показываются**.
- **Страница поста:**
  - ссылка «Bosh sahifa»;
  - h1;
  - серая мета-строка: `10-noyabr, 2026 · ✦ Claude bilan suhbatdan · tahrirlangan 11-noyabr`, где ✦-часть фиолетовая и показывается только при `source`;
  - текст поста;
  - внизу теги.
- Подпись источника зависит от `source`: `Claude bilan suhbatdan`, `ChatGPT bilan suhbatdan`.
- Весь интерфейс на узбекском в новом алфавите, `<html lang="uz">`. Даты в формате `10-noyabr, 2026`. Месяцы: yanvar, fevral, mart, aprel, may, iyun, iyul, avgust, sentabr, oktabr, noyabr, dekabr. От `moment` можно отказаться *(моё решение)*.
- Тексты главной и «About» в этой части только переводятся как есть. Переписываются они в части 4.

### 5.2 Frontmatter (новая схема)
```yaml
title: string            # обязательно
date: YYYY-MM-DD         # дата публикации, обязательно
description: string
author: string           # по умолчанию «Saidafzal Kholkhujaev»
tags: [string]           # заменяет keywords; строчные, в новом алфавите
source: claude | chatgpt # необязательно; есть → пометка ✦
status: draft | published # по умолчанию published
updated: YYYY-MM-DD      # необязательно, ручное переопределение
```
- `keywords` в старых постах переименовываем в `tags`. В `<meta keywords>` по-прежнему идут теги.
- Невалидный frontmatter (нет `title`/`date`, неизвестный `source`/`status`) должен **ронять сборку** с понятной ошибкой, а не тихо подставлять «Untitled».

### 5.3 Отметка «tahrirlangan»
- Дата берётся из git-истории `main`. Правкой считается коммит в `main`, который меняет файл поста и сделан позже **первого** коммита этого файла в `main` (позже хотя бы на день). Показывается дата последнего такого коммита. Поле `updated` в frontmatter, если задано, имеет приоритет. *(моё решение)*
- Чтобы итерации аудита не считались правками, PR с постами мержатся через **squash**: в `main` попадает один коммит.
- Механические коммиты не считаются правками. Это переименование `keywords` → `tags`, массовая конвертация алфавита и т.п. Такие коммиты помечаются трейлером `Yozma-Edit: none`. *(моё решение)*
- В режиме `review` поле `date` выставляется в день создания PR. Каждый коммит в ветку PR (бот, `update_post`) обновляет его на текущую дату, так что после merge дата близка к реальной дате публикации. *(моё решение)*
- В `deploy.yml` нужен `fetch-depth: 0`, иначе история недоступна.

### 5.4 Теги
- Внизу поста теги ссылками ведут на `/teg/<tag>`: статичная страница со списком постов в стиле главной *(моё решение)*.

### 5.5 Черновики
- `status: draft` → пост не попадает ни в список, ни в `generateStaticParams`. Сайт по нему отдаёт 404.
- `working-with-legacy-code-...md` сразу получает `status: draft`. Позже его обсудят, пропустят через флоу и опубликуют.

### 5.6 Диаграммы
- В посте пишется блок ` ```mermaid `. На сайте он отображается как **статичная SVG, отрендеренная при сборке**. Клиентский JS mermaid не используется.
- Палитра в тон сайта: серый и чёрный, фиолетовый только для ИИ-шагов.
- Рендерер и способ рендера выбирает строитель: `rehype-mermaid`/`mermaid-cli`/свой скрипт. Ограничение одно: сборка в GitHub Actions должна работать. Если для этого нужен headless-браузер в CI, это допустимо.
- Пайплайн `remark-html` скорее всего придётся заменить на unified/rehype. Это на усмотрение строителя.

### 5.7 Исправления
- Сортировка по настоящей дате (`date`), от новых к старым.
- Убрать `console.log(posts)` в `posts.tsx`.

### 5.8 Общий модуль «узбекский текст»
Используется скриптами в репо, MCP-сервером и ботом, поэтому он не должен зависеть от Next.js или Node-специфики. Должен работать и в Node, и в Cloudflare Workers.

**Конвертер старая латиница → новый алфавит** (закон OʻRQ-1184 от 21.10.2026, вступает в силу 22.04.2027; мы переходим заранее, это выбор автора):
- `oʻ/o'/o‘/o\`` → `ö`, `gʻ/…` → `ğ`, `sh` → `ş`, `ch` → `ç`, с учётом регистра (`Sh`/`SH` → `Ş`, `Ch` → `Ç`, `Oʻ` → `Ö`, `Gʻ` → `Ğ`). Символы: ö U+00F6, ğ U+011F, ş U+015F, ç U+00E7 (и заглавные).
- `ng` не меняется.
- Тутук (знак-апостроф после гласной или согласной, `maʼno`, `sanʼat`) нормализуется в `ʼ` U+02BC.
- `s` + тутук + `h` (`Isʼhoq`) **не** превращается в ş: между `s` и `h` стоит знак, это не диграф.
- `sh` + тутук + `h` (`mash'hur`): официальных правил ещё нет. Пока получаем `maşʼhur` (`sh` → `ş`, тутук остаётся). Правило должно быть легко поменять *(моё решение)*.
- **Не трогать:** блоки кода и inline-код, URL, mermaid-блоки, frontmatter-ключи, а также слова из списка защищённых (бренды и иностранные слова: ChatGPT, Claude, GitHub, Chrome, Shopify…). Список лежит в репозитории файлом и пополняется.
- Обратная функция «новый → старый» нужна для проверки Tahrirchi (см. ниже).
- Покрыть тестами (TDD), включая все исключения выше.

**Проверка Tahrirchi** (`POST https://websocket.tahrirchi.uz/proofread`, заголовок `Authorization: <KEY>` без Bearer, тело `{nodes:[{offset, fields:[{value, markup:false}]}], ws:1}`, лимит 5000 символов/запрос, 50 запросов/мин, 1 сум/слово):
- Tahrirchi не знает новый алфавит. Поэтому текст в новом алфавите сначала переводится в старый, проверяется, а смещения ошибок мапятся обратно.
- Проверяется только прозаический текст: без кода, URL и mermaid. Текст режется на куски по 5000 символов, по границам абзацев.
- Результат — список `{фрагмент, позиция, варианты}`. Это **подсказки**, а не автозамена: решение принимает модель или автор.
- Ключ `TAHRIRCHI_API_KEY` хранится только в секретах (Worker, GitHub Actions), никогда в коде.

**Линтер поста** (скрипт, например `pnpm yozma:check <file>`). Запускается в CI на PR с изменениями в `posts/`. *(уровни — моё решение)*
- **Ошибки (блокируют `publish_post` и PR-проверку):** невалидный frontmatter; остатки `oʻ`/`gʻ` (в любом варианте апострофа) вне защищённых зон. Эти диграфы не встречаются в английских словах, поэтому ложных срабатываний почти нет.
- **Предупреждения:** остатки `sh`/`ch` вне защищённых зон; попадания из стоп-листа; орфография Tahrirchi; **подозрительные конвертации**.
- **Подозрительная конвертация** — слово, в котором конвертер заменил `sh`/`ch` и которое Tahrirchi при проверке в старом алфавите не признал узбекским (например `fetch` → `fetç`). Эти слова возвращаются списком. Модель (или автор) решает: оформить слово как код, добавить в `protected-words.txt` или оставить. Так иностранные слова ловятся автоматически, а не только по списку.

## 6. Часть 2: MCP-сервер Yozma

- **Удалённый MCP-сервер** (Streamable HTTP) на Cloudflare Workers *(моё решение: бесплатно, нет своего сервера)*. Код в этом же репозитории, в отдельной папке со своим `package.json`, общий модуль из 5.8 переиспользуется.
- Подключается как custom connector **и в claude.ai, и в ChatGPT (оба нужны с первой версии, решение автора)**, а также в Claude Code. Для ChatGPT нужен developer mode: строитель проверяет актуальные требования по тарифу автора перед реализацией и, если что-то не так, сообщает автору до того, как строить.
- **Адрес:** `mcp.yozma.uz` как custom domain Worker'а. DNS yozma.uz уже на Cloudflare (тот же аккаунт, тариф Free), поэтому запись создаётся автоматически при привязке домена. Сейчас в зоне только 8 записей A/AAAA на GitHub Pages (proxied); их не трогаем.
- **Доступ:** пользователь один, автор. Пишущие инструменты доступны только ему. Раз нужны оба клиента: **OAuth 2.1 с входом через GitHub**, пускаем только GitHub-аккаунт автора (`saidafzalkh`). Это поддерживают и claude.ai, и ChatGPT. Реализация на `@cloudflare/workers-oauth-provider` или аналоге, на выбор строителя; токены хранятся в Workers KV.
- **Секреты:** `TAHRIRCHI_API_KEY`, GitHub token (fine-grained, только этот репозиторий, права contents + pull requests).

**Инструменты**
- `get_guide()` возвращает сценарий интервью, стиль-гайд и стоп-лист. Источник правды — файлы в репозитории (папка `writing/`, см. ниже), сервер читает их из GitHub. Так у модели в чате, бота в PR и автора один и тот же стиль-гайд.
- `check_uzbek(text)` → подсказки Tahrirchi (через общий модуль).
- `convert_alphabet(text)` → текст в новом алфавите.
- `publish_post({slug, frontmatter, body, mode: "direct" | "review"})`: валидирует (линтер 5.8, ошибки блокируют, предупреждения возвращаются), конвертирует алфавит, затем:
  - `direct` → коммит `posts/<slug>.md` в `main`;
  - `review` → ветка `post/<slug>` + PR с меткой `post`.
  Возвращает ссылку на коммит или PR и будущий URL поста. Слаг уже занят → ошибка, если это не обновление.
- `update_post({slug, body?, frontmatter?})`: если есть открытый PR `post/<slug>`, коммитит в него. Если пост уже опубликован, спрашивает режим (`direct`/`review`), как при публикации.

**Сценарий в чате** (лежит в `writing/interview.md`; модель получает его через `get_guide`):
1. Автор говорит «давай сделаем из этого пост» (или похожее, на любом языке).
2. Модель задаёт 3–5 вопросов, по одному: главная мысль одним предложением своими словами; с чего началось (конкретный случай); с чем автор не согласен или в чём сомневается; для кого текст; объём (заметка / эссе).
3. Пишет эссе от первого лица на узбекском. **Голос берётся из реплик автора в разговоре**; ответы ИИ служат только фоном, и мысль ИИ, с которой автор просто согласился, не становится центром.
4. Если тема — процесс, сравнение или структура, а схема помогает, добавляет mermaid. Рассуждение обходится без схем.
5. Самопроверка по стоп-листу, `check_uzbek`, исправления.
6. Показывает автору заголовок, теги, описание и текст, затем спрашивает режим: «сразу» или «на аудит».
7. `publish_post`. В frontmatter `source` выставляется по чату: `claude`/`chatgpt`.

**Папка `writing/`** в корне репозитория:
- `interview.md` — сценарий выше;
- `style.md` — стиль-гайд;
- `blacklist.md` — стоп-лист приёмов;
- `protected-words.txt` — слова, которые конвертер не трогает.
Стартовый стоп-лист: пафосные вступления, «xulosa qilib aytganda», «nafaqat… balki…», тройки прилагательных, мораль в конце, риторические вопросы подряд, частые тире, эмодзи. Образцов голоса автора пока нет.

## 7. Часть 3: бот правок в PR

- `anthropics/claude-code-action` в GitHub Actions. Срабатывает на комментарии **автора репозитория** (проверка `author_association == OWNER`) к PR с меткой `post`: обычные комментарии, review и комментарии к строкам. Упоминание `@claude` не обязательно *(моё решение: в PR с постом любой комментарий автора — это правка)*.
- Бот правит `posts/<slug>.md` по комментарию, следуя `writing/style.md` и `writing/blacklist.md`. Затем прогоняет конвертер и линтер (5.8), пушит коммит в ветку PR и коротко отвечает в треде, что сделал.
- Если правка по смыслу означает «звучит как ИИ / шаблонно», бот дописывает в `writing/blacklist.md` новое правило в том же PR. Так стиль-гайд растёт с правками.
- Секреты: ключ Anthropic (или OAuth токен Claude) и `TAHRIRCHI_API_KEY` в secrets репозитория.
- На PR также запускаются сборка и линтер. Превью страницы PR — желательно, но не обязательно в первой версии: GitHub Pages превью не умеет, вариант — Cloudflare Pages preview. Решает строитель.
- Merge PR → обычный деплой.

## 8. Часть 4: контент

- `welcome-to-yozma.md` полностью заменяется постом о новой Yozma, о флоу из этого дизайна. Слаг остаётся тем же, чтобы не ломать URL. Пост пишется **через сам флоу** (первый настоящий прогон), `source: claude`, с mermaid-схемой флоу. *(моё решение по порядку)*
- Часть 4 выполняется **после** того, как части 2 и 3 работают. MCP-сервер подключается и к Claude Code. Флоу запускается в той сессии Claude Code, где шёл исходный разговор о дизайне, или в новой, где этот документ служит материалом. Публикация идёт через `update_post` (пост уже существует) в режиме `review`, чтобы автор прошёл и аудит.- Вступление главной переписывается: коротко о том, чем теперь стала Yozma. Чистота A2 сохраняется. Страница «About» переписывается тоже. Оба текста проходят через стиль-гайд и Tahrirchi.
- Второй пост остаётся черновиком до отдельного обсуждения.

## 9. Ограничения

- Сайт: Next.js static export + GitHub Pages, домен yozma.uz. Хостинг не меняем.
- Пакетный менеджер pnpm. TypeScript strict, без `any` без причины.
- Все секреты только в secrets. Репозиторий публичный.
- Новая логика пишется через TDD (конвертер, линтер, парсинг frontmatter, дата правки).
